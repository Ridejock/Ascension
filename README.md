# Ascension

A LitRPG vertical slice on the [Emerald](https://github.com/Ridejock/Emerald) engine (C++20, SDL3, SDL GPU): turn-based combat and a class change at level 5. This tree is the project skeleton, the JSON data layer, and a combat sandbox. A Fighter earns XP, ranks skills by using them, and at level 5 chooses Berserker or Guardian. The window draws that fight with rectangles and Emerald's built-in debug font.

Emerald is fetched by CMake and pinned to commit `697f356256d7657817e72cbdf27b23731b4821d1` (see `CMakeLists.txt`). That commit's debug font draws `>`, `[`, `]`, `;`, and `%`, and publishes `DebugTextHasGlyph`. To use a local checkout instead:

```sh
cmake --preset debug -DASCENSION_EMERALD_SOURCE_DIR=C:/dev/Emerald
```

## Build

Requirements: CMake 3.24+, Ninja, a C++20 compiler, Git. The presets match [Ridejock/Asteroids](https://github.com/Ridejock/Asteroids): Ninja, `build/<preset>/`, `debug`, `release`, and `debug-full` (ImGui). They work with MSVC on Windows and with GCC or Clang on Linux. The first configure builds [SDL_shadercross](https://github.com/libsdl-org/SDL_shadercross) (the only shader compiler; the build does not call fxc) and caches it for later builds.

### Windows (MSVC)

From a **Developer PowerShell for VS 2022** (x64), so `cl` and `ninja` are on `PATH`:

```powershell
cmake --preset debug
cmake --build --preset debug
.\build\debug\bin\Ascension.exe
```

### Linux (GCC)

SDL's development packages are the same set Emerald documents in `docs/building.md`. On Debian or Ubuntu:

```sh
sudo apt install build-essential cmake ninja-build git pkg-config \
    libx11-dev libxext-dev libxrandr-dev libxcursor-dev libxfixes-dev libxi-dev \
    libxss-dev libxtst-dev libxkbcommon-dev libwayland-dev wayland-protocols \
    libegl1-mesa-dev libgl1-mesa-dev libdrm-dev libgbm-dev \
    libasound2-dev libpulse-dev libudev-dev libdbus-1-dev

cmake --preset debug -DEMERALD_SHADER_FORMATS=SPIRV
cmake --build --preset debug
./build/debug/bin/Ascension
```

`EMERALD_SHADER_FORMATS=SPIRV` matches Linux CI. DXIL (Direct3D 12) is built on Windows. GCC 13's shader compiler crashes on DXIL, so leave that format to the Windows build.

### Linux (Clang)

Same packages, plus `clang`. The preset does not hard-code a compiler; point CMake at Clang for this configure:

```sh
CC=clang CXX=clang++ cmake --preset debug -DEMERALD_SHADER_FORMATS=SPIRV
cmake --build --preset debug
./build/debug/bin/Ascension
```

Release is the same preset name used for the zip (`cmake --preset release`, then `cmake --build --preset release`). Escape closes the window. `--frames N` quits after N frames (an Emerald option). The playtest flags are in [Playtest](#playtest).

## Tests

```sh
ctest --preset debug
```

`release` and `debug-full` are the same kind of test preset. Each one runs the tests in that preset's build directory and prints a failing check.

`AscensionDataTests` loads `tests/data/`, a frozen copy of the data the checks were written against, checks the Fighter tree, and rejects broken files. It also checks that a map grid loads, that a bad id, a missing exit, or a broken legend is named, and that a map reload keeps the last good grid. `AscensionWalkTests` checks tile steps, walls, exits, the camera clamp, a reload that keeps the hero or moves them to the start, and a scripted step where the `stand` mover stays put. `AscensionHandoffTests` checks a spawn fight's win, loss, and flee, a boss that cannot flee, Alpha's Fang dropping once, a cleared spawn that does not come back, an aura status, and a 3-foe cap with a queue. `AscensionCombatTests` plays a Fighter against those sample enemies and checks the damage formula, including a fight that starts from a given HP. `AscensionProgressTests` checks the XP curve, skill ranks, the level-5 choice, the level-up HP rule, a rest point, and a loss that restores HP without taking gold. `AscensionInventoryTests` checks the bag, worn gear, and the shop. `AscensionSaveTests` checks a save round trip, a migration from version 3 (including a fixture save), cleared spawn ids that survive a reorder, an unknown spawn id, Alpha's Fang across that migration, and a truncated file falling back to the previous copy. `AscensionPlaytestTests` checks the playtest flags, unknown ids, a `--data` folder that hot-reloads, an `--art-pack` manifest, and a chain of fights that carries HP. `AscensionDialogueTests` checks talk loading, flag gates, and Pell's lines. `AscensionArtPackTests` checks a manifest, an id that falls back to the built-in art, a strip's frames, a tile's map, theme, and variant, a marker, and a bad path or unknown id being named. None of them open a window. One data check loads the shipped `data/` and asserts that every description expands. It does not lock the wording, so a retune of a number does not move it. The other checks stay on `tests/data/`.

## Data

`data/` is copied next to the executable on every build. A dev build watches the source `data/` (so saving a file in the tree updates the running game) and falls back to the copy beside the executable when that directory is not there, which is what a packaged build does. The game does not care about the working directory. Unit tests load `tests/data/` instead, so the numbers in this folder can change without rewriting the checks.

| File | What it defines |
|---|---|
| `stats.json` | The five combat stats: vitality, strength, defense, agility, focus |
| `effects.json` | Reusable effect recipes. A skill can copy one by id and then tune it |
| `skills.json` | Active skills and passives. Each skill holds a list of effects |
| `statuses.json` | Bleed, Exposed, Enraged, Stunned, Steadfast, and Bloodlust |
| `classes.json` | Fighter, and the level-5 evolutions Berserker and Guardian |
| `enemies.json` | The roster (level, stats, skills, experience, gold), which one is the boss, an optional `unique` flag, an optional `#RRGGBB` `color`, an optional `ai` list, and an optional `drops` list of `{ "item", "message"? }` entries |
| `encounters.json` | Each fight: a name, an optional zone, and a list of enemy ids, at most `maxFoes` (3). The same id may repeat, unless that enemy sets `unique` |
| `items.json` | Gear (weapon, offhand, armor, accessory) and consumables. Each names an `icon` and a `rarity`. An item may set `requires.defeated` to foe ids the shop waits for |
| `rarities.json` | Rarity id, display name, `#RRGGBB` color, and optional `uniquePerType` |
| `shop.json` | Old Pell's Provisions: the bag, stack size, sell rate, Pell's stock, and the dialogue id |
| `dialogue/*.json` | One file per NPC. Nodes, lines, tone notes, and choices |
| `combat.json` | Health per vitality, minimum damage, the attack and defense divisors, focus regen, and `maxFoes` |
| `progress.json` | Total XP to reach each level, uses per skill rank, power added per rank, and the level-up HP rule |
| `tiles.json` | Terrain kinds: id, `solid`, a `#RRGGBB` color, and an optional `sheet` id |
| `walk.json` | Move time, settle time, settle easing, tile size in pixels, the hero's inset, and the hero, exit, and spawn colors |
| `movers.json` | Named map steps. `stand` is `idle`, which does not move. A spawn's `mover` names one |
| `maps/*.json` | One character grid per map: legend, start, spawns, links, and talk, shop, and rest points |
| `input.json` | Every action's keys and buttons, the menu repeat, and the new-game confirm window |
| `prompts.json` | Button glyphs per device family, and the icon and text scales for hint rows |

Pad buttons are positional, so the same `input.json` row is A on Xbox, Cross on PlayStation, and B on a Switch. Keyboard `I` stays Interact and `E` stays Confirm. `A` on the keyboard is MoveWest.

| Action | Keyboard | Pad | What it does |
|---|---|---|---|
| MoveNorth / South / East / West | W A S D and the arrows | D-pad and left stick | Glide on the map while held, then settle onto the next tile on release. In a menu or a fight, move the cursor; left and right also change the target |
| Confirm | E, Enter | South | Speak, buy, equip, drink the marked row, use the marked battle command. On the map, talk or shop |
| Cancel |  | East | Close talk, the shop, the drink list, and pause. Does not quit and does not flee |
| Interact | I |  | Talk or shop on the map, and close talk or the shop. Keyboard scripts keep using `I` |
| Menu | C | West | Camp (party, gear, shop), including on the map. In a fight, the drink list |
| Context | X | North | Inspect the tile or the foe. In the shop, sell a bag row or take off a worn row |
| Pause | P | Start | Pause. East or Start resumes. Escape is still quit |
| Help | H | Back | Show or hide the help line. The map's talk/shop prompt stays |
| CyclePrev / CycleNext |  | LB / RB | Previous and next target, tab, or row, with the same repeat as the d-pad |
| Wait | Space | RT | Wait a turn |
| Flee | F | LT | Leave a fight that allows it |
| Unequip | U |  | Take off the marked worn row. Context does this too |
| Save / Quit / Retry / Next | F5, Escape, R, N |  | Save, save and quit, retry the fight, next foe |
| DebugRespawnFoes | F6 |  | Bring every defeated foe back on every map. Level, gear, gold, and the tile stay. Ignored during a fight |
| DebugNewGame | F9, twice |  | Start a new run. The second press has to land within `debugConfirmMilliseconds`. The save file stays until the next save |
| Slot1–Slot8 | 1–8 |  | The numbered skill, drink, or choice. Confirm uses the marked row when there is no number |

Menu repeat is `navInitialMilliseconds` (280) then `navRepeatMilliseconds` (120). On the map a held direction glides; `walk.json` sets `moveMilliseconds` and `settleMilliseconds`. Hints use the glyph for the action's current binding on the last-used pad. Keyboard, and a button with no tile, draws a short label. `iconScale` and `textScale` in `prompts.json` set the sizes; the text cap is centered on the icon.

Fighter is the base class, and `"starter": true` marks it as a class a build reset can return to. Another starter is that flag on another base class. The list is read from `classes.json`. Berserker and Guardian each set `evolvesFrom` to `fighter` and `evolveLevel` to 5. Berserker **adds two active skills and one passive**. Guardian **adds one active skill and one passive**. A class may also list `picks`: each entry is a level and two or three options, written in the same grant form as `skills`. The choice opens when the hero reaches that level, after the evolve level, and the next fight waits until one option is kept. An option the class already grants has to carry a `tune`; it merges into that skill (best value per field, one shared rank) instead of adding a second copy. Kept picks are part of the build, so Reset build clears them. A base class's `stats` are its attribute grant. An evolution's `bonus` is the attribute grant it adds. `growth` is the attribute points earned by leveling. An evolution's stats are the parent's stats at that level, plus `bonus`, and then its own `growth` for later levels. The choice opens when the hero's level reaches an evolution's `evolveLevel` (5 in the sample), and it stays open until a path is picked, including if the Fighter is already past that level. The next fight will not start until then. The number keys follow the order of those evolutions in `classes.json`, and the next number is Reset build. That is the only place skill ranks are cleared. Ranks are the practiced uses stored on the hero by skill id. A reload does not clear them.

`progress.json` lists the total XP required to be at each level. The first entry is 0. In the sample, 8 XP is level 2, 20 is level 3, 40 is level 4, and 60 is level 5. A win grants the sum of every enemy's `experience` and `gold`, including an add that joined during the fight. Gold is spent at Old Pell's Provisions between fights. The hub itself is a later slice: `I` talks to the shop's keeper after a victory or a defeat, and a `shop_open` choice opens Pell's screen. In encounter order that is Wolf 8, Bandit 18, Tomb Moth 14 (level 4, 40 XP), and Bone Archer 22 (level 5, 62 XP), which opens the choice. Leveling does not heal the fight that just ended. `levelHp` in `progress.json` is what the new max does to the HP the next fight starts with. `gained` adds the increase in max HP, so a full hero stays full and a wound keeps the same missing health. `full` refills. `kept` leaves the wound, then clamps it to the new max. The shipped rule is `gained`. Focus is not part of that rule. The next fight uses the new level and, after a choice, the new class. A win writes the HP and focus that were left, and the next fight starts there. `R` before the fight ends retries from the pools it opened with. A loss fills both pools and marks a return to the hub. The walk back is a later step. Gold is not taken.

A skill starts at rank 1. `usesPerRank` is either one integer (a flat step, `rank = 1 + uses / step`) or a list of the total uses required to reach rank 2, rank 3, and so on. The sample is `[3, 6, 10, 15]`, so the third use is rank 2 and the fifteenth is rank 5, capped by `maxSkillRank`. Each rank above 1 adds `powerPerRank` (2 in the sample) to that skill's damage power, heal power, and a reflect's flat power, including the blow that crosses the rank. A guard's percent is unchanged. The number in parentheses on the skill line is the rank. Ranks live on the hero, keyed by skill id. Evolving keeps the skills the hero already practiced, and those keep their ranks. Reset build, offered only on the evolution choice, is the only thing that clears them. It also returns every class attribute grant to one unspent pool and asks for a starter class. Level, XP, and the points earned by leveling stay, so the total number of attribute points does not change. The player spends the pool, then picks a path. Enemy skills stay at rank 1.

An effect is a `trigger` plus an `op`. Triggers are `always`, `onUse`, `onHit`, `onBlock`, `onTurnStart`, and `onDamaged`. Ops are generic: `stat`, `statPerMissingHp`, `grantFocus`, `damage`, `heal`, `guard`, `reflect`, `empower`, `harden`, `applyStatus`, `stunIfWindingUp`. A skill lists its effects, and each effect has an id. Three layers build the numbers a fight uses. The effect recipe comes first (inline on the skill, or a copy of an entry in `effects.json`). The skill's `tune` replaces fields on those effects. A class, enemy, or item grant can tune the copy again. A later layer replaces only the fields it sets. A tune that names a missing effect, or a field that effect does not have, fails the load and names the file and the field. A field the trigger and op do not read fails the same way, even when another use of that op reads it. Each grant is resolved to its own copy, so two classes can grant Bulwark with different numbers. Battle runs the triggers. It does not look up a skill id.

An effect may set `target` to `self`, `target`, `allEnemies`, `randomEnemy`, or `lowestHpAlly`. That is who the effect hits, and it can be narrower or wider than the skill's own `target`. `target` is the marked enemy when the player acts, and the player when an enemy acts. `allEnemies` is every living member of the foe side other than the user. `randomEnemy` is one of those, walking the pack in order. `lowestHpAlly` is the one of those with the lowest health percent. A tie keeps the earlier seat. From the acting foe those seats are allies, and this aim never selects the player, which is why it is not named `lowestHpEnemy`. An `onUse` heal may set `target`. With no `target`, a heal still restores the user. An `onTurnStart` heal still cannot set `target`, and neither can a guard. A field the op does not read fails the load. Leave `target` off and the effect uses the skill's target.

A damage effect may set `ifTargetHas` to a status id. The blow lands on an aim only while that aim holds the status, and the check happens when that effect resolves, before `onHit`. `consume` is allowed only together with `ifTargetHas`. The status stays up for the rest of that use, so every damage effect in the use still sees it, that use does not apply the same status to that aim again, and the status is removed after the last `onHit` effect. The log names the foe and the status (`Oathkeeper Varn loses Exposed.`). A miss is not a hit: `onHit` and `consume` reach only aims a damage effect actually struck. Two damage effects that hit one foe in one use are one blow line. Rank bonus is added once per damage effect, and a damage-dealt percent such as Fury multiplies every damage effect that lands.

Bulwark is that shape in the sample:

```json
{ "id": "bulwark", "name": "Bulwark", "kind": "passive", "effects": [
  { "id": "def", "trigger": "always", "op": "stat", "stat": "defense", "amount": 3 },
  { "id": "focus", "trigger": "onBlock", "op": "grantFocus", "amount": 1 } ] }
```

Bloodlust, the Berserker passive, is `always` / `statPerMissingHp`: 1 strength for every 10 percent of health missing, up to 6. That passive keeps the id `bloodlust`. The Dire Wolf's self-buff is a different skill, `dire_bloodlust`, and the status it applies is also named Bloodlust. It does not change the strength shown as a stat; it is added when a blow scales with strength. Bulwark's `stat` adds 3 defense, and its `grantFocus` pays 1 focus when a guard actually reduces a hit. Defense by itself does not. Riposte costs 2 focus. Its `guard` stops 70 percent of the next hit, and its `reflect` returns 50 percent of the damage that guard stopped plus `power + defense`. What returns meets the attacker's defense the way a hit does. Shield Bash costs 3 focus. It strikes with defense, leaves the foe Exposed, and a foe who is already Exposed takes a second blow and loses Exposed. Rend costs 2 focus: a cut, then a deeper cut that needs Bleed and leaves it, and Bleed is applied twice on the hit. Rally costs 3 focus and sets a guard while knitting a small wound. A class that wants a different Bulwark grants it with a tune, for example `{ "skill": "bulwark", "tune": { "focus": { "amount": 2 } } }`. The string `"bulwark"` uses the recipe as written. Items may list the same `grants` array; the loader resolves those copies, and a worn piece's grants join that fight. Any class can wear a piece. The grant is not tied to a class id.

A hit is `power + scaling stat`, minus defense, and then at least `minDamage`. The attack divisors are 1 in the sample, so the scaling stat is added whole. Defense is `defense` × `defenseNumerator` / `defenseDenominator` (1/2), so it counts half, rounded down. Status percents apply after that formula: damage dealt, then the guard, then damage taken. Brace's guard `amount` is the percent of the next hit that is ignored. Max health is vitality times `hpPerVitality`. The hero's focus pool is `focusBase` (4) plus their focus stat. It rises by `focusPerTurn` (1) at the start of their turn, and waiting adds `focusOnWait` (2) on top of that. Enemies do not regenerate focus. Higher agility acts first each round; a tie lets the Fighter go first. The order comes from a turn model (`AgilityRoundModel`), so a later active-time model can replace it without rewriting damage.

`statuses.json` defines Bleed (3 health at the start of each of the afflicted unit's turns, for 3 turns, stacking to 2), Exposed (+25 percent damage taken, 2 turns), Enraged (+30 percent dealt and +15 percent taken; the sample keeps it up for a fight), Stunned (skips the next action), and Steadfast (cannot be stunned or Exposed for a short while). Bloodlust deals 25 percent more damage for 99 turns. The Bandit's Slash bleeds on every third use. Heavy Blow stuns a foe who is winding up and cancels that wind-up, unless a status they hold resists stunned. The foe's panel shows the telegraph (`AIMED SHOT 1/2`, then `INCOMING`), a raised guard (`GUARD 75%`), a defense buff with the turns still left (`DEFENSE +150 (2)`, the word taken from Defense in `stats.json`), and any statuses.

An enemy may set `ai`, an ordered list of rules. The first match wins, and a rule left unused leaves the pattern in charge. `do` is `pattern` or `skill`, and a skill has to be one of that enemy's own grants. A condition that is left off is not tested. A health percent compares current health × 100 with maximum health × the percent. `allyHpAtMost` uses that comparison on the other living foes as one pool: their current health added together, against their maximum health added together. Dead foes are in neither total. If the acting foe has no other living ally, `allyHpAtMost` does not hold. `allyCountAtMost` and `allyCountAtLeast` count those same other living foes. The acting foe is not one of them, and a dead foe is not either. 0 means the allies have all fallen. The loader accepts 0 to 9. The Dire Wolf is the first foe with rules. While it holds the Bloodlust status it bites. Otherwise it uses `dire_bloodlust` when the hero's health is at most 45 percent, or when that ally pool is at most 60 percent. Howl, Stalk, and Circle are self skills that grant 0 focus, so the turn deals no damage. The Bear is the other foe with rules. At 40 percent health or below, and while it is not already Enraged, it uses Enrage. While the hero is not Bleeding it uses Rending Maul. Otherwise the pattern plays: Heavy Swipe, Rending Maul, Heavy Swipe.

`items.json` is the gear and the drinks. Each item has an `icon` id from `assets/icons/icons_sheet.json` and a `rarity` id from `rarities.json`. The sheet is the untinted steel-grey picture. `icons_accent_sheet.png` holds the same rectangles, accent pixels only, and the shop multiplies those by the rarity color and draws them over the base. The item name uses that color. Source maps and the generator are in `art/icons/`, and the master palette is `art/palette.gpl`. From any directory, `python3 art/icons/make_icons.py` reads that palette and `icons.txt` (both relative to the script) and rewrites `assets/icons/`. Adding an icon is a new map in `icons.txt`, then that command. Mythic sits above Legendary. A rarity may set `uniquePerType`: at most one item of that rarity for each `slot`. Slot is the item type (weapon, offhand, armor, accessory, consumable). The load fails when a second item of that rarity uses the same slot, and the error names both items. The check reads the flag, not the id `mythic`. Alpha's Fang is the mythic accessory (strength +2, agility +2, 80 gold). It uses the `ring` icon already on the sheet, so it adds no picture. It grants `fang_bloodlust` (1 focus, the Bloodlust status, a different id from the Berserker passive). Pell does not sell it. The Dire Wolf's `drops` list grants it on a victory. That entry's `message` is the victory log line: "The Alpha falls. The fang slides free, still warm." A drop that omits `message` keeps the generic line, `Found` plus the item name. The first kill finds it. A later kill does not, including when `R` fights that foe again, and including after the fang is sold. The save's found list is those claimed item ids. A version 3 file with no such list has claimed nothing, and version 4 keeps the list, so the fang is still claimed after the migration. A weapon may set `twoHanded`, which fills the offhand as well. Oak Shield is an offhand. Consumables are not worn: `heal` is flat health and `focus` is flat focus, spent as a turn in a fight. The sample is Rusty Sword (strength +1, 12 gold), Notched Greataxe (strength +6, defense -2, two-handed, 60 gold), Oak Shield (defense +2, 15 gold), Oathkeeper's Plate (defense +6, agility -1, 55 gold), Wolfhide Charm (agility +2, 35 gold), Minor Potion (heal 30, 10 gold), and Focus Tonic (focus +4, 15 gold). The sword, the axe, and the plate prices are the ones chosen for this slice. Notched Greataxe and Oathkeeper's Plate set `requires` to `{ "defeated": ["oathkeeper_varn"] }`, so Old Pell keeps those rows until that foe has fallen. The row still shows the name and the price. Selling pays half the buy price, rounded down (`sellNumerator` 1, `sellDenominator` 2).

`shop.json` is Pell Harrow's shop, Old Pell's Provisions. `bagSlots` is 12 and `stackSize` is 5, so a sixth potion of the same kind opens another slot and sixty potions fill the bag. Worn gear is added to the class stats before passives. A two-handed weapon sends the offhand piece back to the bag, and a shield cannot be worn until that weapon comes off. If a reload makes the worn weapon two-handed while a shield is still in the offhand, the shield's defense stops immediately and the shield is moved into the bag. A full bag sets the last stack down to make that slot. The offhand can always be taken off. The fight starts with an empty bag and no gold. Number keys stop at 8, so the menu action opens every consumable stack during the player's turn. Drinking still spends the turn. Keys and buttons are `input.json`. The game asks Emerald for the action and does not check a scancode or a face button.

`shop.json` may name a `dialogue` id. That file is `data/dialogue/<id>.json`. `I` starts the talk wherever the shop would have opened, and `I` closes it again. A node has an id, a line, an optional `note` (tone, not drawn), and `choices`. A `/` in a line is a box break. The box also wraps at 40 characters. The menu marks the row with `>`. MoveNorth and MoveSouth change the row, Confirm speaks, and Cancel or Interact closes it. On a pad those are the d-pad or left stick, South, and East, from `input.json`. A choice has text and one of `next` (a node id), `end` (closes the talk), or `action`. `shop_open` is the action that opens the shop screen. The first node whose `requires` hold is the start. A requirement is a flag: `met`, `!met`, or `list.id`. `found.alphas_fang` reads the run's found list, the same list that records a claimed drop. `sets` on a node or a choice stores a plain flag. Lines are not descriptions: a `{placeholder}` fails the load.

`tiles.json`, `walk.json`, and `maps/*.json` are the overland grid. A launch with no `--enemy` and no `--sim` opens the hub. Unless the command builds a hero, that launch reads the per-user save and stands on the saved tile. `--map id` opens that map instead. Without `--save-dir` it does not load or write the per-user save. `--enemy id` stays on the fight screen, and `N` there still walks `encounters.json`. Arrows, WASD, the d-pad, and the left stick move the hero, through Emerald's move actions, so those bindings can be changed without touching the motion code. A pad uses the same actions: South confirms and interacts, East cancels, West opens the camp or the drink list, North inspects, Start pauses, Back toggles the help line, the shoulders cycle targets, the right trigger waits, and the left trigger flees. Hints draw the glyph for the bound button on the last-used pad (Xbox, including a Steam Deck or a generic pad, PlayStation, or Switch) at the scale in `prompts.json`, and a short text label when the device is a keyboard or the glyph is missing. The cap of that label is centered on the icon. `walk.json` is the held move (`moveMilliseconds` for one tile) and the glide onto a tile after release (`settleMilliseconds`, and `easing` of `linear` or `smooth`). Holding a direction moves continuously, with no pause on each tile. Releasing glides to the next tile in that direction. The committed tile changes when the drawn point reaches that tile, and that is when a rest, a spawn, or an exit runs. The file also sets the tile size, the hero inset, and the hero, exit, spawn, rest, talk, and shop colors. A file that omits a point color keeps the palette default (`fol1`, `skinA1`, `leath2`). A solid tile or the edge of the grid blocks. Stepping onto a link moves to that map's arrival tile. Landing on a link, including an arrival that is itself a link, does not take it. The view keeps the hero on screen and does not slide past the map edge; a smaller map stays centered. The grid, the exit, a spawn, and the hero are palette rectangles. The corner names the map and draws the carried HP and focus. Stepping onto a rest point, including a start tile that is one, refills both and logs `Rested.` Stepping onto a spawn starts that encounter at the carried HP and focus. A win clears a spawn whose `once` is set, the rectangle goes away, and the hero keeps the HP and focus that were left. A loss returns to the hub's rest point, or the hub's start when it has no rest. When no map sets `hub`, the loss returns to the fought map's rest, then its start. Both pools are full and gold is kept. `F` flees, unless the spawn sets `noFlee` or a foe sets `boss`. The hero steps back to the tile they came from, or the first open neighbor, the spawn stays, and that foe's HP is kept for the next contact. Cleared ids and those wounds are stored by spawn id. Inserting or reordering a spawn does not move a cleared id onto a different foe. An id the data no longer has is kept and ignored until that spawn exists again. An empty id is a damaged file. Standing on a talk point and pressing `I` opens that point's dialogue. Standing on a shop point and pressing `I` opens the shop. Saving `walk.json`, `tiles.json`, or a map reloads: the hero stays when that tile is still walkable, and otherwise goes to the map's start (or another map's start, if this map is gone). A tile has an id, `solid`, and a `#RRGGBB` `color`. `sheet` is an optional id and is not opened yet. A map file's id matches its file name. `rows` are strings of equal length, one character per tile, and `legend` maps each character to a tile id. `x` grows east and `y` grows south, both from 0. `start` is the hero's tile. A spawn has an id (unique across every map), a tile, and an encounter id. `once` defaults to true, so a cleared spawn is meant to stay cleared. `noFlee` defaults to false. `mover`, when listed, names a behavior from `movers.json`. The only kind is `idle` (`stand`), which stays on its tile. Each time the hero reaches a tile, every listed mover is asked, so a later kind can chase or forage on that same step. A mover whose tile changes is drawn gliding to it at the move speed. An optional `aura` is a radius and a status id. When a fight starts, another spawn inside that radius carries the status. The spawn that lists the aura does not grant it to itself. A contact seats at most `maxFoes` and leaves the rest queued for a later fight. The hub's spawns do not set `mover` or `aura`, so those fights are unchanged. A link names the target map and the arrival tile. A point is `talk` (a dialogue id), `shop`, or `rest`. A rest point may share the start tile. Other markers do not share a tile, and none of them may stand on a solid tile. At most one map sets `"hub": true`. The loader checks tile ids, encounter ids, dialogue ids, and that every link's map and arrival tile exist. A missing `maps/` folder is no maps, the same way a missing `dialogue/` folder is no talks. The shipped maps are `hub` and eight rooms: `barrow_1` through `barrow_7`, plus the side room `barrow_side`. The hub has Pell's existing talk, the shop, a rest on the start tile, and the door into the barrow. The rooms are the wolf and the bandit, the tomb moth and the bone archer, a rest, the Barrow Sentry, the bear, an optional Wolf Pack room, a rest, Oathkeeper Varn, the Cairn Warden, a rest, and the Barrow Brute. The brute's spawn sets `noFlee`. Varn stays the roster's one `boss`, so that fight also refuses flee. A cleared spawn does not come back. `tests/data/maps/` keeps the two fixture maps the loader tests walk. Saving a map or `tiles.json` uses the same hot reload as the other data files. A bad file keeps the previous maps and names the file and the field.

A description may contain `{placeholders}` filled from that entity's own fields. There is no arithmetic and no conditional. A brace that is not a real field fails the load and names the file, the entity, and the placeholder, for example `skills.json: skill 'bulwark' description: unknown placeholder {def.amout}`. The same expander runs when the screen draws the text, so a rank or an item tune shows the numbers on that copy. Damage and reflect `{power}` add `(rank - 1) * powerPerRank`. A new hero is the first class with `"starter": true`.

| Entity | Placeholders |
|---|---|
| Skill | `{name}` `{cost}` `{windup}` (only when windup is set). Per effect: `{id.power}` `{id.amount}` `{id.percent}` `{id.per}` `{id.max}` `{id.turns}` `{id.every}`. `{id.stat}` and `{id.scaling}` are the stat's name. `{id.status}` is the status's name, and `{id.status.dealt}` (also `taken`, `perTurn`, `turns`, `stacks`, `name`) reads that status. `{id.ifTargetHas}` is the name of the status that effect requires. |
| Status | `{name}` `{turns}` `{stacks}` `{perTurn}` `{dealt}` `{taken}`, and only when that number is set |
| Class | `{name}` `{evolveLevel}` `{from}` (the parent class's name). A base class uses `{paths}` (the children's names joined with " or a ") and `{pathLevel}` (their evolve level, which has to be the same) |
| Enemy | `{name}` `{phaseAt}` `{summon}` (the summoned enemy's name) `{summonEvery}` |
| Item | `{name}` `{value}` `{heal}` `{focus}` |

Shop, bag, and worn rows share one facts suffix: heal, focus, each bonus by its name in `stats.json`, "two handed", `grants` plus the skill name, and the rarity's display name. Descriptions stay off those rows. A worn row keeps the slot and the item name and skips the price, the heal, and "two handed". The camp title is `shop.name`. The buy refusal uses the keeper's full name. The help key and the between-fights note use the keeper's first word.

The public headers (`include/Ascension/Data/`, `include/Ascension/Combat/`, and `include/Ascension/Progress/`) are plain structs, the battle, the hero's career, and the bag. JSON parsing and the error text live in `src/Data/Database.cpp`. A bad file names itself and the field, for example `classes.json: class 'berserker': skill 'smash' does not exist`. Unknown keys are errors, so a typo does not silently do nothing.

While the game is running it checks the data files a few times a second. A save is applied once the new modification time has been seen twice, so a half-written file is left alone. If the new text does not load, the previous definitions stay and the error is shown, naming the file and the field. The revision in the corner goes up on every successful reload. The fight keeps its wounds and whose turn it is. XP and skill uses are kept too: editing the curve or `usesPerRank` updates the level and the ranks on the next successful reload, and class growth applies on the next fight. Edit Strike's `power` in `data/skills.json`, Bulwark's defense `amount`, or `hpPerVitality` in `data/combat.json`, save, and the next blow uses the new numbers.

## Save

`F6` (`DebugRespawnFoes`) clears defeated foe ids and cleared spawn ids on every map. Stats, level, XP, worn gear, the bag, gold, and the tile stay. Claimed drops stay claimed, and a flee wound stays, because that foe was not defeated. An ongoing fight, and a map fight that has not settled, leaves the lists alone and shows the busy line. `F9` (`DebugNewGame`) arms a confirm, and a second press within `debugConfirmMilliseconds` (1500) starts the run a missing save starts: the first starter, level 1, an empty bag, full health, and the hub's start tile. It does not delete or rewrite the save. The next `F5` or quit writes that new run over the file. Both actions are keyboard only. The four lines (`debugRespawned`, `debugRespawnBusy`, `debugNewGameArmed`, `debugNewGame`) are in `input.json`. While the help line is on, the map, the fight, and the between-fights screen show those two keys. `design/debug.md` is the same note.

`F5` writes the run. Escape writes it and quits. The next launch loads that file, unless the command builds a hero of its own (`--level` and the other setup flags). The file is Emerald's text save, data version 4, one slot named `run` under the per-user Ascension folder (`~/.local/share/Ridejock/Ascension/saves/run.sav` on Linux). A write goes to a temporary file and is renamed into place. A truncated file falls back to the previous copy. The save holds the class, XP, stats, skill uses, kept picks (a tuned upgrade included), gold, bag stacks, worn gear, the carried HP and focus, the defeated foe ids, the found drop ids, the map id and tile, cleared spawn ids, flee wounds, and the encounter id when the fight screen is in use. It does not store an encounter-list index. A victory resumes between fights at the HP that was left, so the reward is not granted again. A flee keeps that HP and the foe's wound. An ongoing fight restores each foe's wound, statuses, pattern step, and whose turn it is, and prints Resumed before anyone acts. On a map, that fight also records the spawn id it came from. A version 2 ongoing file has no foe snapshot, so that encounter starts over.

A version 3 file migrates one step, through the same registered chain as older files. `position` was an index into `encounters.json`, not a tile. The step renames it to `legacy.index` and, once the maps are loaded, turns it into the encounter id at that index (or the first encounter, when the index is past the end). The hero is placed on the start tile of the map that sets `hub`. When no map sets it, the first map in file order is the stand-in. A spawn whose `once` is set is cleared when its encounter id is in the defeated list. The list stores foe ids, and a one-foe encounter uses that same id, so those match. The wolf pack's encounter id is not a foe id, so that spawn is not cleared. A spawn with `once` false stays up. Spawn ids are taken from the data loaded at that moment; a spawn added after the run is saved as version 4 is not cleared by the old index. A victory or a defeat does not keep the old health field, which is what version 3 already did. An ongoing fight keeps its HP and its snapshot, and it has no spawn id. Found ids, including Alpha's Fang, are not touched. The per-user save is only read by a normal launch, or by `--map` together with `--save-dir`. Copy a version 3 file into that folder to migrate it. `--map` alone does not open the per-user save. `playtest/outer-barrow/save-commands.txt` is a save, quit, and load run. `playtest/dialogue/commands.txt` talks to Pell and walks the rumor.

## Combat

Run the game and you are on the hub, at the rest. `--enemy wolf` is the Wolf fight on the fight screen. The Wolf is faster, so it bites first. Then:

| Key | Action |
|---|---|
| `1` `2` `3` `4` | Strike, Brace, Heavy Blow, Second Wind |
| `5` `6` | After evolving: Berserker Rage and Cleave, or Guardian Shield Bash and the next free drink. Before that, the first consumables in the bag |
| The next free number, through `8` | A kept pick, then a drink. A drink spends the turn. A stun keeps the bottle. Eight keys is the cap: a bar that is already full leaves drinks on `C` |
| `C` | During your turn, open or close the drink list. Up and Down move. `E` drinks the marked row. `1`–`8` drink that row. Any drink spends the turn |
| Space | Wait. Also gains 2 focus on top of the 1 gained at the start of the turn |
| `F` | On a map fight, flee when the spawn allows it. A boss (`noFlee`, or a foe with `boss` set) refuses and does not spend the turn. A fight from the encounter list has no flee |
| `I` | On a talk tile, open that dialogue. On a shop tile, open the shop. On the fight screen, between fights, talk to the shop's keeper, or close that talk or the shop. During a fight, the keeper is not there |
| Up Down | In the shop, move through the bag or the stock |
| Left Right | During your turn, when the fight has more than one enemy, change the marked target. Dead enemies are skipped. In the shop, switch between the bag and the stock |
| `E` | In the shop, equip the highlighted bag item, take off the highlighted worn piece, or buy the highlighted stock |
| `X` | In the shop, sell one of the highlighted stack |
| `U` | In the shop, take off the highlighted worn piece |
| `R` | Fight this encounter again from the HP and focus it opened with. A finished win has already written those pools back, so the rematch starts at what was left. A loss has restored both. Level, XP, gold, gear, and skill ranks stay. Refused while a path is still open |
| `N` | On the fight screen, the next encounter in `encounters.json`, at the HP and focus the last fight left. A loss restored both, so that fight starts full. While a path is open the fight does not start and the encounter stays put. On a map fight, the next fight is the next spawn |
| `F5` | Save the run |
| Escape | Save the run, then quit |

On the fight screen the encounters, in list order, are Wolf, Bandit, Tomb Moth, Bone Archer, Wolf Pack, Barrow Sentry, Bear, the boss Oathkeeper Varn, then the Cairn Warden and the Barrow Brute. `N` walks that list. The map does not: its order is the rooms above, and the Wolf Pack is the optional room before Varn. The corner of the name shows the place in that list. When an encounter sets `zone`, that text is drawn above the foe name. The Cairn Warden and the Barrow Brute set it to Outer Barrow. A fight with no zone leaves the line off, and the log does not include it. A single enemy fills the right panel. A pack draws one column per enemy (a rectangle, the name, health, a wind-up, a guard or defense buff, and a status). The marked enemy is framed and labeled TARGET. The enemy whose turn it is is labeled ACTS, and the banner uses that name. Varn is marked BOSS. The Wolf Pack is one Dire Wolf leading two Wolves. Dire Wolf sets `unique`, so an encounter can list that foe once; any other foe can set the same flag and a fight may include several different unique foes. A foe with `color` is drawn as a square of that color: the Wolf is light grey (`#C8C8C8`), the Dire Wolf is dark grey (`#3A3A3A`), and the Bear is leather brown (`#7E4E2E`, `leath1` on the project palette). The fight ends when every enemy is dead. The Dire Wolf pays 20 XP and 3 gold, and each Wolf pays 8 XP and 3 gold (36 XP and 9 gold). Its pattern is Bite, Howl, Stalk, Circle, Stalk. Howl, Stalk, and Circle deal no damage, so the wolves do most of the biting. Once, when the hero is at 45 percent health or the other living wolves together are at 60 percent of their combined health, it uses Bloodlust on itself and then bites every turn. The Bear is one foe, and it sets `unique`, so a fight can list it once. It stands after the Barrow Sentry. Its pattern is Heavy Swipe, Rending Maul, Heavy Swipe. While the hero is not Bleeding it mauls, and at 40 percent health it becomes Enraged if it is not already. It pays 20 XP and 24 gold.

After a win that reaches level 5 the skill list is replaced by the choice, and the next fight waits. `1` is Berserker. `2` is Guardian. `3` is Reset build. A later win that reaches a skill pick replaces the list the same way: `1` and `2` (and `3`, when a pick offers three) are the options, in file order. An upgrade reads `UPGRADES` and the skill's name. That screen has no reset. Guardian's level-6 pick is Riposte or Shield Wall, and level 8 is Rally or Rage. Berserker's level-6 pick is Rend or Brace, and level 8 is Rally or Second Wind. Reset clears skill ranks, puts the class attribute grants back in a pool, and lists every starter class. `1` is Fighter in the sample. After that, `1` through `5` spend the pool on vitality, strength, defense, agility, and focus, and `6` resets again. The path keys return once the pool is empty. Reset is not offered anywhere else. The new skills show once a path is picked. `R` then fights the same encounter again, and `N` is what moves on. Pressing `N` before the choice does not skip ahead. Wolf, Bandit, Tomb Moth, and Bone Archer are 8 + 18 + 14 + 22 XP, which is level 5. The next fight is the Wolf Pack (20 + 8 + 8 XP), which reaches level 6. The Barrow Sentry is met at level 6, and its 40 XP reaches level 7. The Bear is met at level 7. Its 20 XP leaves the total at 158, still short of level 8, so Varn is still met at level 7. Varn's 80 XP reaches level 8. The Cairn Warden (30 XP and 14 gold) is met at level 8, and the Barrow Brute (40 XP and 20 gold) is met at level 9.

Varn's pattern is Maul Swing, then Crushing Slam (telegraphed, then it lands), then Stone Skin. Phase 2 starts at 60 percent health: Varn becomes Enraged. Every second action in that phase the panel names the Rubble Shard, and Varn's next action calls it into the fight. A second shard does not join while one is still up: that turn Varn takes his ordinary action instead. The fight holds at most `maxFoes` enemies (3 in `combat.json`). The shard has to die too. A corpse does not keep its seat: once it falls, Varn can call another, and a second copy is numbered the same way a wolf pack is (Rubble Shard, then Rubble Shard 2). Cleave hits every living enemy. The line under the skill says who each damage, status, and stun effect hits, using that effect's `target`. Change Cleave's effect `target` to `target` and the line says the marked enemy, which is also who the swing hits. Heavy Blow (`3`) stuns a wind-up and cancels it, which is the Berserker's answer. Riposte or Shield Wall, once that pick is kept, is the Guardian's answer to a telegraph. Shield Bash is the Guardian's class attack. The Bone Archer's Aimed Shot is the same kind of telegraph, two turns long, so it can be practiced before the boss. Its pattern is Aimed Shot, then Bone Bolt: cancelling the draw still lets the bolt fly on the next action. Edit `data/encounters.json`, or an effect's `target`, save, and the next action uses the new fight.

Waiting against the Wolf loses. Strike three times and it dies (8 XP, level 2). `N` starts the next foe at the HP and focus that were left.

## Playtest

A scripted run sets the hero and the fight from the command line, so a playtest does not have to grind or edit `data/`. Emerald still owns `--frames`, `--screenshot`, `--capture`, `--capture-fps`, `--record`, `--replay`, `--profile`, and `--profile-trace` (and `--gpu`). Ascension reads the flags below and leaves those alone. A value can be the next argument or `--flag=value`. Fights are deterministic: damage, turn order, and foe AI do not use a seed. `--sim` can still mark a random living foe from `--seed`. A one-enemy fight does not use that mark.

| Flag | Effect |
|---|---|
| `--transcript file` | Append every on-screen log line: blows, gold, XP, shop notes, path choices, build resets, a target change (`Target: Wolf 2.`), each enemy Cleave hits, and a summon (`Rubble Shard 2 joins the fight`) |
| `--data dir` | Load that folder instead of `data/`. A save there hot-reloads, the same check the game already runs |
| `--art-pack dir` | Replace pictures from that folder's `manifest.json`. With no flag, `artpack/` next to the executable is used when it exists. With neither, the built-in CC0 art is drawn. The format is [design/art-pack.md](design/art-pack.md) |
| `--level N` | Start at level N. N has to be on the curve in `progress.json` |
| `--class id` | Start as that class. An evolution is taken only when that choice is open, so `--level` has to be at least the path's evolve level |
| `--enemy id` | Start on that fight. An id from `encounters.json` (such as `wolf_pack`) is that encounter. An id from `enemies.json` that is not an encounter is that one enemy. When an id is both, the encounter wins |
| `--map id` | Open that map and walk it. Omitting it opens the hub. No fight starts until a step lands on a spawn, which starts that encounter at the carried HP and focus. Without `--save-dir` this launch does not load or write the run save. With `--save-dir` it resumes that folder: the tile, HP, focus, cleared spawns, and flee wounds. The id is a file under `data/maps/`. Pass this or `--enemy`, and this or `--sim`, not both |
| `--sim` | Play an encounter with no window. `--enemy` is required and has to be an encounter id, unless `--chain` or `--route` is set. With no `--class` and no `--focus`, it prints a rate table: each class build, each kill order, with and without Alpha's Fang. Wolf orders are the dire wolf (then a wolf), a wolf (then the dire wolf), and default. A one-enemy fight, such as the Barrow Sentry or the Bear, is one row. The sim uses level 6, a rusty sword, and an oak shield. Each of those fights starts full, so a single row does not change when HP can carry. A self-buff that only raises damage dealt is cast when the status percent in `statuses.json` shortens the kill by more than the turn it costs. Rage is still spent while health is above half. Pass this or `--keys`, not both. A loss still exits 0 |
| `--chain` | With `--sim`, walk `encounters.json` in order and carry HP and focus from a win into the next fight. A loss restores both, and the next fight starts full. No `--enemy`, `--focus`, `--runs`, `--seed`, or `--slip`. The kit is the same level-6 sword and shield, with no fang. The pack kills the dire wolf first. `--class` and `--pick` limit the builds |
| `--route` | With `--sim`, walk the maps from the hub and carry HP and focus the same way. A rest on that walk refills both before the next fight. It prints two runs for each build: main, which skips the optional room, and fang, which takes it and wears a drop from a win there. No `--enemy`, `--map`, `--focus`, `--runs`, `--seed`, or `--slip`. The kit matches `--chain`. `--class` and `--pick` limit the builds |
| `--focus id` | With `--sim`, the enemy id that one build kills first. Empty marks a random living foe each turn |
| `--runs N` | With `--sim`, how many seeds to play when the mark can change. Default 1000. Range 1 to 100000. A named focus with `--slip 0`, and any one-enemy fight, is one outcome, so the Runs column stays 1 |
| `--seed N` | With `--sim`, the first xorshift32 state. Default 1. `0` is stored as 1. It only chooses the player's mark |
| `--slip N` | With `--sim`, the percent of player turns that ignore a named focus and mark a random living foe. Default 0, so a named order stays exact. Range 0 to 100 |
| `--gold N` | Start with N gold |
| `--give id[:count],...` | Put items in the bag. A missing count is 1 |
| `--equip id,...` | Wear those pieces. An id that was also given comes out of the bag; anything else is added and then worn. A two-handed weapon still fills the offhand |
| `--keys "1 1 c e r"` | Press those keys in order, one per frame after the window is up, then quit. The names are the combat table: `1`–`8`, `c`, `e`, `u`, `x`, `i`, `r`, `n`, `f`, `space`, `up`, `down`, `left`, `right`, `escape`, `f5`, and on a map also `w`, `a`, `s`, `d`. The window does not need focus |
| `--keys-file path` | The same list, read from a file. Pass this or `--keys`, not both. `f5` saves |
| `--save-dir path` | Read and write the run save in that folder. Empty uses the per-user Ascension saves directory. A command that builds a hero (`--level`, `--class`, `--enemy`, `--gold`, `--give`, `--equip`, `--choose`, `--pick`) does not load a save. `--map` loads one only when this flag names the folder |
| `--choose id` | When the evolution choice opens, pick that class |
| `--pick id` | When a skill pick opens, keep that option. Repeat the flag for each pick, in the order the picks open |

An unknown id stops the process before the window opens, and the message names the id. The same is true of an unknown key, a missing folder, a bad art-pack manifest, and a transcript that cannot be opened. A relative `--data` or `--art-pack` path is relative to the working directory. `--art-pack` does not change the hero or the save. A key script ends on its last frame, which is the frame `--screenshot` saves, unless `--frames` asks for a different length.

```
Ascension.exe --data playtest-data --level 6 --class berserker --enemy oathkeeper_varn --keys "1 1 3 1" --transcript varn.txt --screenshot varn.png
```

That is a level-6 Berserker against Oathkeeper Varn. The four keys are Strike, Strike, Heavy Blow, and Strike. `varn.txt` collects the log, and `varn.png` is the last of those frames. `oathkeeper_varn` is an encounter id, so the fight is the one in `encounters.json`.

```
Ascension.exe --level 6 --class berserker --enemy wolf_pack --keys "6 right 6" --transcript pack.txt
```

That is the same Berserker against the Wolf Pack. `6` is Cleave, which logs a hit on each living Dire Wolf. `right` marks the next one and logs `Target: Dire Wolf 2.` A Varn fight that calls a second shard logs `Rubble Shard 2 joins the fight.` Those lines are in the transcript because they are the on-screen log. `playtest/bear/commands.txt` runs the headless bear and sentry tables.

```
Ascension.exe --save-dir %TEMP%\ascension-step6 --keys "d d i down down e e a a s s i i" --transcript walk.txt
```

That is a throwaway save folder, not the per-user save. The hub start is the rest, so the log says `Rested.` Two steps east and `i` talks to Pell. Down twice and `e` takes "Just passing through.", and the next `e` ends that line. Two steps west and two steps south stand on the shop, and `i` opens it and the next `i` closes it. `playtest/hub/commands.txt` continues through the door into `barrow_1` and onto the wolf. `playtest/route/commands.txt` is the headless map route: one table for every build, with and without the optional room. `--enemy wolf` is still the single fight on the fight screen. A launch with no `--keys` stays on the map until Escape.

## Art pack

A private build can point `--art-pack` at a folder, or place `artpack/` next to the executable. `manifest.json` maps tile, foe, hero, NPC, and overland marker pictures onto PNG files in that folder. A tile row can name one map or one theme, and a list of variants for that tile. A picture can be a horizontal strip with a frame count. An id the manifest leaves out keeps the built-in CC0 art. The folder is gitignored and is not in the public zip. [design/art-pack.md](design/art-pack.md) is the format.

## Package

```sh
cmake --build --preset release --target package
```

writes `build/release/Ascension-<version>-<platform>.zip` (the executable, shaders, `data/`, licenses, and `.itch.toml`). A local `artpack/` folder is not part of the zip. CI calls Emerald's reusable workflow `Ridejock/Emerald/.github/workflows/game.yml@main` for Windows (MSVC) and Linux (GCC). The itch.io user and game slug are left empty, so a tag does not publish.
